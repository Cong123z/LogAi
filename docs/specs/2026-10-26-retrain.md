# Retrain: baseline rebuilds, re-reads from ES, schedule and history

Status: **implemented** (tasks 51-60, merged into master 2026-10-27; proof: docs/perf/2026-10-26-retrain.md). Plan: `docs/plans/2026-10-26-retrain.md`.
Mockup (4 boards): https://claude.ai/artifact/VdaHzwwbkVPkWYDMAofnsa.
Replaces the 2026-10-22 backfill design for the production layout: one index per
service per UTC day (`udcntt-<service>-YYYY.MM.dd`), ES keeps **7 days**.

## 1. Goal

A **Retrain** page (Settings) that shows only:

1. the **current run** as logai-engine shows it: a status sentence, then each step with its time and one
   detail line (docs, hours replaced, new templates, rate, position), a progress bar in the current step,
   the run's warnings in a collapsible log, Cancel;
2. the **history** of runs, succeeded or failed; a row opens its details;
3. a one-line **schedule** (on/off, time, week days);
4. **Run retrain**: kind, services, days, hours.

Baseline maturity per service stays on the Baseline page (its "Baseline" card).
Baseline and Review move from Settings to Catalog in the nav.

## 2. Two kinds of run

| Kind | What it does | Time |
|---|---|---|
| **Rebuild** | mark finished days, rebuild `baseline` from stored counts (today's daily commit) | seconds |
| **Re-read** | read the chosen services / days / hours again from ES, **replace** their stored counts, then Rebuild | minutes to hours |

Re-read is for a new pattern's past days, hours the engine was down, and hours
that lost late docs (B4). With 7 days in ES a weekday profile can become full;
a weekend profile at most young (full needs 4 weekend days).

## 3. Re-read

**Scope:** services (all or chosen) x days (the last 7 local days) x one hour
range (`from` - `to`). The engine drops hours before the oldest doc in ES
(writing them would store zeros) and hours at or after the owner's current
hour (live still writes them).

**Lane:** in the engine thread, only when live is caught up, 1 s per tick.
Reads the selected patterns that contain the chosen services (`index_services`)
with its own `OpenMinutes`, shares the Drain3 miners, never runs detection.

**Replace per whole hour, in the owner's flush:** delete the hour's rows of
`service_hours`, `hourly_counts`, `template_module_hours` for the service and
insert the lane's, with the run position in the same transaction. A stored hour
is never half old, half new; a crash resumes from the position.

**End:** reached the end -> Rebuild, `succeeded`. Cancel or failure (ES error 3
times, exception) -> replaced hours stay, no Rebuild. Engine restart -> resumes.
One run at a time: Run retrain is disabled while one runs (409). Live detection
is not muted.

## 4. Schedule (`settings.retrain_schedule`, revisioned)

`{enabled: true, time: "02:00", weekdays: [0..6]}`; never saved = config
defaults. Off or a skipped day only skips the Rebuild: day marking, partitions
and retention run every night. A missed run (engine down) runs at start.

## 5. History (`retrain_runs`)

`id, kind, trigger (schedule/manual/startup), scope, state (running/succeeded/
failed/cancelled), started_at, finished_at, pos_ms, steps, result, error,
error_type, failed_step, log` (WARNING+ lines while it ran, max 50). Steps: `scope`, `read`, `rebuild`. Result: docs read,
hours replaced, days marked, baseline rows. Kept 365 days.

The table shows: started, kind, scope, duration, result. Details: the error (if
any), each step with its time and one line, and the result.

## 6. API

| Method | Path | |
|---|---|---|
| GET | `/api/retrain` | schedule + revision, next run, current run, last 50 runs |
| PUT | `/api/retrain/schedule` | `{schedule, revision}`; 409 on mismatch |
| POST | `/api/retrain/runs` | `{kind, services, days, hour_from, hour_to}` -> 202; 409 if one runs; 400 on an empty scope |
| GET | `/api/retrain/runs/<id>` | one run with steps |
| POST | `/api/retrain/runs/<id>/cancel` | 202 |
| POST | `/api/baseline/recompute` | kept: a manual Rebuild |

The estimate (docs, time) comes from an engine command, shown in the dialog.

## 7. Risks

| Risk | Handling |
|---|---|
| Minute counted twice (lane + live) | scope ends at the owner's current hour; whole-hour replace |
| Service fed by two patterns | read every selected pattern that contains it |
| Old minutes dropped as late | lane has its own `OpenMinutes` |
| Zeros for hours not in ES | scope clamped to the oldest doc in ES |
| Missing partitions for past days -> flush stalls (B1) | `ensure_partitions` at run start |
| `templates.first_seen` not moved earlier | `LEAST` (Phase 1) |
| Index deleted by retention during a run | that span ends; warning in the run's details |
| Live lag | lane runs only when live is caught up, 1 s per tick |
| Template flood -> LLM drafts | the dialog warns when an LLM profile is active |
